# Architecture

## Scope

The model is a low-latency semantic parser built on a pretrained ASR model. It
accepts the current audio turn plus optional bounded conversation context and
returns structured output. It never produces the final user-facing answer and
never executes a robot action.

```text
microphone audio + bounded dialogue context
                    │
                    ▼
       Qwen3-ASR speech-to-action SLM
                    │
          ┌─────────┴─────────┐
          │                   │
          ▼                   ▼
 non_tool(text=...)      robot tool call
          │              (partial args allowed)
          ▼                   │
    cloud agent               ▼
                       agent harness validates
                              │
                    ┌─────────┴─────────┐
                    │                   │
              missing field       complete call
                    │                   │
              follow-up TTS              ▼
                                    execution layer
                                    state + safety + I/O
```

## Model contract

For every completed audio turn, version 1 returns exactly one route:

- `non_tool` with the recognized Vietnamese transcript in `text`; or
- one robot function call with the tool name and every argument that the user
  supplied in the current turn or that is unambiguous from supplied context.

The model must:

- omit missing arguments rather than fabricate defaults;
- preserve corrections and self-repairs in speech (the last clear value wins);
- avoid resolving state-dependent references that require live robot state;
- use the tool catalog provided in the request unchanged;
- produce no natural-language answer outside the tool call.

Version 1 intentionally limits each turn to one route. Multi-action commands
will be evaluated before deciding whether to support parallel tool calls or
route them to the cloud agent.

## Harness contract

The future agent harness owns the conversation loop. It receives the SLM
result and:

1. forwards `non_tool.text` and conversation context to the cloud agent;
2. validates a robot call against the selected function schema;
3. asks a deterministic follow-up when required fields are absent;
4. supplies prior turns back to the SLM for slot completion;
5. sends complete calls to the execution layer;
6. turns execution results or cloud responses into user-facing speech.

The follow-up question is not generated by the SLM. This is the same useful
separation demonstrated by VoiceTeller, adapted here to a combined
audio-to-tool model rather than separate ASR and text-SLM stages.

## Execution-layer contract

The execution layer is authoritative for:

- current robot pose, mode, battery and capability state;
- argument ranges, units, defaults and normalization;
- safety rules, collision constraints and confirmations;
- action dispatch, timeouts, cancellation and status reporting.

Training data must not teach the SLM to imitate this stateful behavior.

## Evaluation axes

Evaluation will be reported separately for:

1. route accuracy (`non_tool` versus robot action);
2. tool-name accuracy;
3. argument precision, recall and exact match;
4. missing-field behavior (correctly omitted versus hallucinated);
5. slot completion across follow-up turns;
6. `non_tool` transcript WER/CER;
7. acoustic robustness (noise, distance, accent, silence and robot playback);
8. latency, TTFT, TPS and real-time factor on edge hardware.
